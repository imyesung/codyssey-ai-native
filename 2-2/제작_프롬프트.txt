첨부한 개정 기획서.md와 assets/를 읽고, 10분 발표와 발표 뒤 읽기에 쓸 ‘미션에서의_AI_활용법_v2.html’ 한 파일을 만들어 줘. 최초 A/B 제작 뒤에 나온 피드백을 반영하는 재제작 요청이야. 최초 입력과 결과는 그 버전으로 남겨 두고 새 이름으로 저장해 줘.

1. 한 파일 안에 CSS와 바닐라 JavaScript를 넣고 더블클릭으로 열리게 해. 외부 녹화는 기획서의 고정 HTTPS를 쓰고, 원본 SVG·코드와 첨부한 화면 캡처는 HTML을 단독으로 열었을 때도 볼 수 있게 넣어 줘. 글꼴은 기기에 설치된 것으로 사용해. 본문과 Prompt에는 비례폭, 코드에만 고정폭을 써. 서버, 외부 라이브러리, 로그인, API 키, 실행 중 AI 호출은 필요 없어.
2. 페이지를 처음 열면 ‘저장 위치 / 영화 추가 / 초기화 / 2배 확대’ 네 탭과 ‘저장 위치’ 전후 영상이 화면 상단에 바로 나오게 해. 두 영상은 준비되는 즉시 함께 재생해. ‘미션에서의 AI 활용법 네 가지’는 브라우저 title과 화면 낭독기용 h1에 보존하고, 화면 위의 큰 제목·부제·소개 전용 여백을 없애 줘. 넓은 흰 화면에 왼쪽 목차와 읽기 열을 놓고, 글보다 그림을 크게 써. 화면 소제목은 ‘저장 위치’, ‘같은 손동작’, ‘피드백 도식’ 같은 짧은 명사구를 써. “나는 어떤 화면을 깔끔하다고 느꼈지?”는 레퍼런스 절의 본문에 둬. 여백·정렬·활자로 영역을 나눠 줘. 하단 진행 바, 중첩 카드, 장식 배지와 Prompt 편집기는 제외해.
3. 수정 전/후 실제 영상과 비교 코드는 1440px 창에서 합계 1040px 이상·각 열 490px 이상, 1280px에서 합계 920px 이상·각 열 430px 이상으로 보여 줘. 390px에서는 위아래로 쌓아 각 340px 이상을 확보해. 600~680px 본문 폭은 글에만 적용해. 같은 시각·같은 좌표에서 원본 픽셀을 잘라 판정 장면 두 개를 크게 놓아 줘. 저장 위치 사례의 23·38·57번 프레임에서 S와 A, 손끝, 실제 테두리, 〈기생충〉을 각각 확인해. ‘전체 장면’에서는 같은 시각에 원래 화면 전체를 보고 돌아올 수 있어야 해. 각 원본 HTTPS 링크도 줘.
4. 사례 탭은 ‘저장 위치 / 영화 추가 / 초기화 / 2배 확대’ 네 개야. 한 번 선택하면 같은 사례의 영상 두 개, 캡션, ‘코드 보기’에서 열릴 실제 변경 구간과 줄 링크를 함께 바꿔 줘. 같은 시계로 처음부터 반복하고, 두 영상을 한 버튼으로 멈추고 이어 봐. 짧은 영상의 마지막 프레임은 두 영상이 함께 되감길 때까지 유지해. 움직임 줄이기 설정에서는 정지부터 시작해. cases.json의 실제 코드·들여쓰기·줄바꿈을 보존하고 변경 줄을 알아볼 수 있게 해. 저장 위치에는 수정 두 구간, 영화 추가와 초기화에는 다른 진입점과 같은 수정, 확대에는 화면 경계 계산이 보여야 해.
5. 1-3의 figure.svg 원본 하나를 인라인으로 넣어. 도식 단계에 진입한 첫 화면에 SVG의 제목, 세 열, 네 행과 네 모서리가 모두 보이게 해. 1000×1148의 원본 비례를 유지하고, 실제 보이는 브라우저 영역에서 상단 UI와 고정 목차·절 제목 높이를 뺀 가로·세로 안에 contain으로 가운데 정렬해. 주소창·창 크기·배율이 바뀌면 다시 맞춰. 도식 내부에는 스크롤을 두지 말고 글자를 크게 읽을 네 행의 원문 표는 바로 아래에서 독립적으로 펼칠 수 있게 해. 레이아웃 절에는 기획서의 1인칭 도입 다음으로 한국어 OpenAI 기준 화면 한 장과 여섯 본문 화면을 차례로 놓아 줘. 첫 화면은 assets/references/openai-ko.jpg, 원문은 https://openai.com/ko-KR/index/codex-collaborator-creative-team/ 야. 이어 Thariq, Simon, Maggie, Robin, Frank, Mike 순서야. 한 화면에는 이미지 한 장이 고정 UI와 캡션을 제외한 가용 공간을 원본 비율로 최대한 채워야 해. → 한 번이면 다음 한 장, ← 한 번이면 이전 한 장이야. 그림 바로 아래에는 짧은 출처 링크와 기획서 독자용 갤러리에 적힌 감상 한 줄을 그대로 써. 390px에서는 캡션이 자연스럽게 줄바꿈되게 해. 원문 제목과 긴 설명 대신 이미지와 한 줄을 한눈에 볼 수 있게 해.
6. 첫 화면의 ‘저장 위치’에서 →를 네 번 눌렀을 때 ‘영화 추가 → 초기화 → 2배 확대 → 같은 손동작(Prompt 1. 재현 영상)’ 순서로 이동하게 해. 같은 손동작에서 ←를 네 번 누르면 정확한 역순으로 저장 위치에 돌아와야 해. 본문에서나 네 탭에 초점이 있을 때나 같은 경로를 유지해. 각 탭의 ‘전체 장면’과 ‘코드 보기’, 원본 녹화 링크는 직접 선택해 여는 기능으로 두고, 첫 네 번의 이동에 추가하지 마. Tab·Enter·Space로 상세 내용과 재생을 조작하고 닫기나 Esc로 보던 사례에 돌아올 수 있게 해. 같은 손동작 이후에는 원문 표 네 행, 한국어 기준 화면과 여섯 캡션, 수정 네 건과 미해결 두 건, 세 판본, Gemini 검토 예시, 도구 표, Prompt와 공유 지침을 양방향으로 읽게 해. 갤러리는 그림과 짧은 캡션을 한 번에 방문하고 다음 키에서 다음 한 장으로 전환해. 긴 본문은 가용 높이의 약 72%씩 움직여 이전 내용이 20% 이상 겹치고 마지막 줄까지 보이게 해. 링크 열기와 복사는 사용자가 직접 실행해.
7. 화면 제목, 캡션, 목차, 복사 버튼에서 ‘Prompt 1. 재현 영상 / Prompt 2. 피드백 도식 / Prompt 3. 단일 HTML 사례 / Prompt 4. 기준 사례 비교 / Prompt 5. 사례 조합 / Prompt 6. 독립 검사’라는 이름을 일관되게 써. 복사 버튼은 ‘Prompt 1 복사’처럼, 네 지침은 ‘공유 지침 1 복사’처럼 써. 개별 복사와 전체 복사에서 기획서 인용문과 줄바꿈을 그대로 보존해. Gemini 문구는 ‘Gemini 검토 예시’로, 375px에서의 19/31은 제작 AI의 당시 보고로, 가운데 판본 S/A는 실제 이벤트 처리 코드에서 읽은 결과로 표시해. 검사 절은 프레임과 코드 줄에서 다시 해 볼 조작과 기대값으로 끝내.
8. 읽기판을 넣을 때는 현재 절을 유지하고 반복 재생을 멈춰 같은 장면 곁에 설명을 둬. 인쇄에서도 각 사례와 안내 문장이 보이게 해. 1440px·1280px·390px, 글자 200%, 움직임 줄이기, 네트워크 차단 상태에서 기획서 T1~T3을 확인해. 첫 화면에서 → 네 번·← 네 번의 실제 방문 순서를 적어 줘. 390×844, 844×390, 1280×720 노트북, 브라우저 200% 확대에서 도식 단계 첫 화면을 찍고 네 모서리가 고정 UI 밖의 가시 영역 안에 있는지, 내부 스크롤이 없는지, 원문 표를 따로 펼칠 수 있는지 확인해. 각 사례에서 직접 상세를 열고 닫아 긴 코드 끝줄·전체 영상과 원래 탭 복귀를 확인해. 같은 손동작 이후에는 정방향과 역방향으로 캡션·일곱 그림·Prompt 1~6·공유 지침 1~4를 실제로 본 위치를 대조해 줘. 결과 HTML과 직접 관찰한 브라우저 조건·측정값·남은 차이를 별도로 돌려줘.
