# Codyssey Mission AI 활용법

## 발표본의 기준

2026년 11월 10일 발표에 쓴 `missionthon-ai-tips-yesunglim.html`을 2-2의 최종본으로 정했다. 두 AI의 최초 결과를 비교한 뒤, 화면의 크기와 이동 순서, 제목과 원고를 고쳐 발표에 사용한 파일이다. 11월 12일에도 이 발표본을 최종 기준으로 지정했다.

최초에 두 AI에게 전달한 문서와 발표를 마친 뒤의 기획은 구분한다. [최초 공통 기획서](참고/최초_공통기획서.md)와 [공통 제작 요청](참고/최초_공통요청.txt)은 당시 입력 그대로 보존했다. 이 문서는 실제 발표 파일에 맞춰 정리했다.

## 대상과 목적

같은 입학연수 미션을 해 본 코디세이 동료에게 보여 주는 자료다. 발표 중에는 한 사람이 키보드로 화면을 넘긴다. 발표 뒤에는 동료가 같은 파일을 열어 자기 과제와 가까운 사례와 요청문을 찾는다.

먼저 결과를 보여 주고, 다음에 그 결과를 받은 요청문을 읽는다. 수정 전후 녹화에서는 손끝 아래의 칸, 화면에 표시된 테두리, 실제로 저장된 등급을 구별한다. 피드백 도식에서는 확인한 문제와 기획서의 기준, 사용성을 위한 제안을 구별한다. 레퍼런스에서는 막연히 깔끔한 화면을 주문하는 대신 실제 페이지의 여백과 이미지 배치를 비교한다.

## 화면과 조작

| 순서 | 화면 | 조작 |
| --- | --- | --- |
| 1 | 제목과 발표 소개 | 다음 버튼이나 `→`로 이동한다. |
| 2 | 저장 위치, 영화 추가, 초기화, 2배 확대 | 네 탭을 차례로 방문한다. 수정 전후 녹화를 함께 멈추고 재생한다. |
| 3 | 같은 손동작과 Prompt 1 | 요청문의 구절을 누르면 비교할 장면을 짚어 준다. |
| 4 | 피드백 도식, 원문 표, Prompt 2 | 도식 전체를 본 뒤 원문 표를 따로 펼친다. |
| 5 | 레이아웃 레퍼런스 | OpenAI 기준 화면 뒤에 여섯 사례를 한 장씩 본다. 각 캡처에는 원문 링크와 감상이 붙는다. |
| 6 | Prompt 3~6 | 사례 검색, 기준 사례 비교, 사례 조합, 결과 확인 요청을 읽는다. |
| 7 | Q&A | 발표를 마친다. `←`로 마지막 요청문으로 돌아갈 수 있다. |

저장 위치에서 `→`를 네 번 누르면 영화 추가, 초기화, 2배 확대, 같은 손동작 순서로 간다. `←`는 반대 순서다. 긴 글은 한 번에 끝으로 넘기지 않고 앞부분과 겹치게 이동한다. 전체 영상과 코드 비교는 직접 열어 보는 상세 자료다.

표지와 소개, 마지막 Q&A는 발표 때 고른 구성이다. 이전 제작 요청에 있던 ‘표지 없이 첫 영상부터 시작하기’로 되돌리지 않는다. 발표에서 제외한 별도의 독립 검사 실물 화면, 도구 목록, 공유 지침 네 개도 이번 기획서에 구현한 기능으로 적지 않는다. 결과 확인 요청인 Prompt 6은 남아 있다.

## 파일과 자료

CSS와 JavaScript, 여덟 녹화와 일곱 레퍼런스 캡처를 HTML 하나에 담았다. 서버나 설치 없이 파일을 열 수 있고, 연결이 끊겨도 녹화와 그림, 본문을 볼 수 있다. 원문 링크를 방문할 때는 인터넷 연결이 필요하다.

피드백 도식은 기존 `1-3`의 SVG이고 녹화와 비교 코드는 `1-4`에서 가져왔다. 이번 작업에서는 두 폴더의 파일을 고치거나 stage하지 않는다. 외부 페이지의 캡처는 기존 발표본에 들어 있는 것을 그대로 쓴다. 캡처마다 저자 또는 발행처의 원문 링크가 있다. 자료 준비 당시 수업과 설계 검토용으로 캡처했으며, 별도 공개 배포 허락은 확인하지 않았다는 기록을 유지한다.

## 완료 기준

1. 네 사례를 고르면 같은 사례의 전후 영상과 코드가 보인다. 함께 멈춘 뒤에는 두 화면이 움직이지 않고, 전체 장면 보기에서는 잘라 낸 부분까지 확인할 수 있다.
2. 피드백 도식의 네 행과 세 열이 한 화면에 들어간다. 일곱 레퍼런스와 Prompt 1~6을 빠뜨리지 않고 읽을 수 있다.
3. 390px 화면과 네트워크를 끈 상태에서도 본문과 내장 자료를 볼 수 있다. 좁은 화면에서는 목차를 펼쳐 이동한다.

실제 관찰은 제작검증기록의 세 테스트에 적었다. 발표 파일에는 요청문을 읽는 기능이 있지만 복사 버튼은 없다. 복사, 별도의 읽기 전환, 인쇄용 정지 화면은 2-3에서 추가한다.

## 한계와 비목표

1. 이 파일은 과거 작업을 설명하는 발표 자료다. 페이지 안에서 AI를 호출하거나 새로운 검사 결과를 만들지 않는다.
2. 녹화는 기존 브라우저 실험의 기록이다. 실물 휴대폰이나 모든 브라우저에서 같은 현상이 나타난다고 일반화하지 않는다.
3. 청중 로그인, 답변 수집, 원격 조작, 슬라이드 편집기는 만들지 않는다.

## 제작 도구와 검증 방법

최초 후보는 OpenAI Codex의 GPT-6 Astra(`xhigh`)와 Claude Code의 Claude Opus 5.5로 만들었다. Claude의 노력 설정은 당시 화면에 ‘엑스트라’로 표시됐다. 서로 다른 설정 명칭을 임의로 같은 값이라고 적지 않는다.

두 최초 파일에 같은 작업을 한 기록과, 실제 발표본을 다시 연 결과를 나누어 본다. 녹화의 저장 등급과 코드, 도식의 조건 유무, 요청문 원문을 대조한다. 현재 파일을 검사한 조건과 관찰 주체는 제작검증기록에 명시했다.
