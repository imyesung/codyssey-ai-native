## 1. 제출 트리

```text
.                               [직접] 저장소 루트. 저장소 이름 미지정
├── docs/                       [예시] 네 문서를 모을 한 폴더

├── README.md                   [예시][선택] 네 문서의 순서와 한 줄 소개
└── ...                         [직접][선택] 보너스 기록과 이미지. 위치와 이름 미지정
```

이름은 세 가지로 나뉩니다.
- [지정] 원문이 정한 이름: 이 미션에는 없습니다. §2 끝 문단은 트리를 "참고할 수 있다"고만 합니다.
- [예시] 원문 트리에 나온 이름: 그대로 써도 되고 바꿔도 됩니다.
- [직접] 원문에 이름이 없습니다. 직접 정합니다.

원문이 정한 제출 조건은 여섯 가지입니다.
1. 네 문서를 한 폴더에 모읍니다 (§2 끝 문단).
2. GitHub 저장소에 올리고 저장소 URL을 제출합니다 (§2 끝 문단).
3. 문서는 Markdown 또는 PDF로 씁니다. 트리 예시의 .md 대신 .pdf를 써도 됩니다 (§2 끝 문단).
4. 대화 로그에는 편집하지 않은 원문을 넣습니다. 화자 표기와 지점 표시만 덧붙일 수 있습니다 (§2 끝 문단, §7).
5. API 키, 비밀번호, 계정 이메일은 적지 않습니다 (§2 끝 문단, §7).
6. 개인정보와 사내 기밀이 없는 과업을 고릅니다 (§7).

## 3. 작업 순서

줄 형식은 "행동 (근거 절). 결과: 넣을 파일과 항목. 다음 값: 뒤에서 쓸 값."입니다.
판단이 필요한 줄에는 "직접 입력"을 붙였습니다.
AI에게 맡길 줄 아래에는 복사할 프롬프트를 달았습니다. 프롬프트의 빈칸은 채워서 보내면 됩니다.
모델을 고른 이유, 프롬프트를 고친 이유, 막힌 과업과 그 이유, Pass와 Fail 판정은 직접 해야 합니다 (§7). 그래서 이 네 곳에는 프롬프트를 달지 않았습니다.
모든 줄에 공통으로, 한 줄을 끝내거나 막히면 run-log.md 작업 기록에 한 항목을 씁니다. 한 항목에는 작업 하나만 씁니다 (§4-5). 막힌 항목은 39번에서 미해결 후보가 됩니다.
파일 이름은 트리의 예시 이름으로 적었습니다.

### 준비

1. GitHub 저장소를 만든다 (§2 끝 문단). 결과: 저장소. 다음 값: 저장소 URL (45번). 직접 입력: 저장소 이름과 공개 범위. 둘 다 미지정이다.
2. 한 폴더에 위 빈 양식으로 네 파일을 만든다 (§2 끝 문단). 결과: docs/의 네 파일. 다음 값: 파일 경로.

### 과업 정의 (§4-1)

3. 자기 업무에서 반복되는 과업 하나를 고른다 (§4-1). 결과: system-design.md / 과업 정의 / 과업. 다음 값: 과업 문장. 직접 입력: 개인정보와 사내 기밀이 없는 과업 한 문장 (§7). 정의해 둔 과업이 있으면 참고한다.
4. 과업 정의의 나머지 칸을 채운다 (§4-1, §4-3). 결과: system-design.md / 과업 정의. 다음 값: 입력 데이터 형태, 출력 규격 (6, 12, 14번). 직접 입력: 타겟 사용자, 입력 데이터 형태, 출력 규격, 업무 문제.
5. 비교와 대화에 함께 쓸 입력 자료 하나를 준비한다. 결과: 따로 싣지 않는다. 대화 로그에 남는다. 다음 값: 입력 자료 (9, 15번). 직접 입력: 개인정보를 뺀 자료. 날짜나 숫자가 있으면 검증 질문을 만들기 쉽다 (§4-6 괄호).

## 작업 기록

- `docs/`에 제출 양식 4개가 있는지 확인했다.
- 새 미션의 전문에서 제출 트리, 빈 양식, 작업 순서표를 뽑는 일을 과업으로 정했다.
- 모델 비교에 쓸 공통 지시문 초안과 첫 입력 자료를 준비했다.
- 본 비교에 Claude Opus 5.5와 ChatGPT GPT-6.2 Astra를 골랐다. 모델 2종에 쓸 설정은 `Max effort`다.
- LG K-EXAONE 2.5의 Google Apps Script 호출은 선택 과제인 BONUS 3에서 시도하기로 했다.
- 세 번째 모델로 DeepSeek V4.1을 골랐다. 공식 웹의 갱신 공지와 공개 모델 카드를 확인하고, BONUS 응답까지 얻으면 같은 기준으로 모델 4종을 대조하기로 했다.
- 같은 v1과 1-1 시험 자료를 새 웹 대화 3곳에 보냈다. ChatGPT와 Claude의 실제 Max 설정을 확인하고 DeepSeek은 DeepThink OFF, Search OFF로 실행했다.
- 본 대화 전에 페르소나, Few-shot 예시 3쌍, 검증 기준과 원문에서 답을 찾을 질문 5개를 준비했다.
- 웹 서비스 3곳에서 보낸 메시지를 다시 복사해 공통 입력 파일과 대조했다. 입력 3개 모두 UTF-8 22,562바이트이고 SHA-256이 일치했다.
- ChatGPT의 안내서와 ZIP을 따로 내려받아 압축에 든 Markdown 양식 4개가 안내서 본문과 일치하는지 대조했다.
- DeepSeek의 제출 트리에서 예시 파일명을 고정한 문장과 키 미발급을 일괄 허용한 점검표를 찾아 과제 안내의 「최종 결과물」과 「BONUS 3」에 대조했다.
- BONUS용 개인 Apps Script에 `runBonus3`를 저장했다. 웹 비교 때 쓴 입력을 그대로 보내도록 했고 전송 전에 SHA-256을 검사한다.
- DeepSeek에 작업 순서표 수정을 2번 요청했다. 두 번째 답에서 파일명의 선택 여부는 고쳐졌고 48~50번의 대화 순서와 한 행의 행동 수가 남아 미해결 기록에 옮겼다.
- BONUS의 첫 Apps Script 실행은 13시 15분 49초에 시작했다. LG API가 응답하기 전에 요청 시간이 초과됐다. HTTP 상태와 답변 본문은 수신하지 못했다.
- BONUS의 두 번째 호출은 같은 입력을 유지하고 API의 추론 설정만 `low`로 바꿔 실행했다.
- Claude가 완성한 48,729바이트 안내서를 내려받아 본문, 양식 4개, 작업 순서표와 점검 항목 34개를 확인했다.
- 모델 3종의 응답을 모델 이름과 설정별 폴더에 보관했다. Claude와 DeepSeek은 응답에 실린 양식 4개를 개별 파일로 분리하고, ChatGPT는 원본 ZIP의 파일 4개를 그대로 풀었다.

- 모델 3종의 첫 대화에서 공개 웹 사용 여부를 확인했다. Claude는 이전 채팅을 검색했고 ChatGPT는 작업 파일을 검색했다. 외부 웹 검색 사용은 모델 3종 모두 X였다.
- 내가 매긴 점수와 선정 이유를 비교 보고서에 옮겼다. 선정 모델은 Claude Opus 5.5 / Max다.
- 15시 43분 33초에 예시 없는 지시문을 Opus 새 대화에 보냈다.
- 15시 44분 25초에 다른 Opus 대화에 같은 지시문과 예시 3개를 보냈다. 두 대화에 첨부한 파일은 같은 `1-1_spec.md`다.

- 16시 8분 53초에 검증 질문 1, 2를 보냈다. Opus는 답과 함께 원문 행을 제시했다.
- 16시 12분 31초에 표 형식을 지정하고 질문 3, 4를 보냈다. 받은 표의 머리글은 ‘답’과 ‘근거’였다.
- 16시 16분 40초와 16시 19분 31초에 질문 5를 같은 문장으로 보냈다. 두 응답 전문이 같은지 대조했다.
- 16시 22분 5초에 v2를 같은 모델의 새 대화에서 실행했다. BONUS 기록과 제출의 순서를 확인하기 위해 같은 원문을 첨부했다.

- v2 응답을 열어 v1 작업표와 순서를 대조했다. v2에서는 39번에 API를 호출하고 40번에 결과를 기록한다. 43번에 GitHub에 올리고 마지막 45번에 저장소 주소를 제출한다. README의 문서별 소개 양식에는 ‘제안’이라고 표시했다. [v2 응답 전문](../responses/claude-opus-5.5_max/experiment/v2-result.md)
