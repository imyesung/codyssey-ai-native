# 시스템 설계 문서

## 과업 정의

나에게는 정보를 선형적으로 따라가는 방식이 미션을 이해하는 데 잘 맞는다.
그런데 미션 원문은 제출할 최종 결과물 4가지를 먼저 소개하고, 이어서 기능 요구 사항 9가지를 번호순으로 정리하는 순서로 쓰여 있다.
개인 학습 특성에 따라 미션을 이해하려니 여러 절을 오가고, ‘참고’할 절을 훑어보다가 작업 단위를 정하는 데 실패하곤 했다.
원문을 받으면 내가 무엇부터 순서대로 할지 세우는 일이 먼저 필요했다.

그래서 코디세이에서 새 미션을 받을 때마다 나는 원문에서 제출물과 작업 순서를 정리한다.
`미션명_spec.md` 한 개를 넣으면 제출 폴더 트리, 파일별 빈 양식, 위에서부터 한 줄씩 따라갈 작업 순서표를 받는다.
원문의 수량과 예외까지 빠짐없이 반영한다.

## 페르소나와 시스템 프롬프트 전문

**카테고리**

페르소나. 아래 역할과 규칙을 Claude Opus 5.5 / Max의 새 채팅 첫 메시지에 넣었다. 과제 안내 6장은 웹 서비스의 지침 입력란과 첫 메시지 중 하나를 사용할 수 있도록 한다(과제 원문 199행).

````text
이름: 미션 정리 담당
역할: 코디세이 수강생이 미션을 시작할 수 있게 제출물과 작업을 정리한다.
전문 분야: 한국어 과제 명세, 제출 구조, 조건과 증거 대조
말투: 짧은 한국어 문장. 한 줄에 행동 하나.
금지 사항: 원문에 없는 파일명, 수량, 실행 결과를 필수로 만들지 않는다.
우선순위: 원문 조건 보존, 필수와 선택의 구분, 복사 가능한 양식, 작업 순서.
출력: 채팅 답변 본문에 제출 트리, 빈 양식, 작업 순서를 차례로 쓴다.
````

## 유저 프롬프트 v1

v1은 역할을 맡은 모델에 제출 트리, 파일별 빈 양식, 작업 순서표를 만들어 달라고 요청한 첫 버전이다. Opus 실험에서는 아래 v1과 시스템 프롬프트를 한 메시지에 넣고 `1-1_spec.md`를 첨부했다. Zero-shot과 Few-shot은 같은 역할과 v1을 사용했다. Few-shot에만 입력과 기대 응답 예시 3쌍을 붙였다. [Zero-shot 첫 메시지 전문](../responses/claude-opus-5.5_max/experiment/zero.txt) [Few-shot 첫 메시지 전문](../responses/claude-opus-5.5_max/experiment/few.txt)

첫 모델 비교에는 코디세이 1-1에 첨부된 원문을 사용했다. [코디세이 과제 전문 (Login 필요)](https://usr.codyssey.kr/learning/learningMap?projectNo=164003) 아래 지시문 뒤에 같은 전문을 붙여 웹 모델 3종에 한 번씩 보냈다. 입력란에서 서비스가 긴 글을 파일로 바꾸면 원본 텍스트로 되돌린 뒤 전송했다.

**입력 자료 식별**

`1-1_spec.md`의 SHA-256은 `50d5f730b9ffdf7fbdd8b5706dda185c31cd68c01b1363af12c1ffc4242e70cc`다. v1과 전문을 합친 공통 입력의 SHA-256은 `6fde63a60eca5db44f34be1eea22e1ffe1ca225b802b61367b5a0adfa19f90f9`다. BONUS 호출 때는 이 두 번째 값을 대조한다.

**카테고리**

텍스트 생성. 이 지시문과 첫 입력 자료를 합쳐 비교 모델 3종에서 사용했다.

````text
나는 새 미션을 받은 코디세이 수강생이다. 아래 미션 원문 한 편으로 이 과제를 시작할 수 있게 다음 세 가지를 작성해 줘.

1. 제출할 폴더와 파일을 고정폭 코드 블록의 트리로 보여 줘. 원문이 정한 이름, 예시로 든 이름, 이름을 직접 정할 수 있는 경우를 구분해 줘.
2. 각 파일 아래에 그대로 복사할 빈 양식을 붙여 줘. 원문에 표가 있으면 열과 순서를 보존하고, 작성 예시는 예시로 표시해 줘. 파일 형식이 코드, 이미지, 영상 등이라면 실제로 필요한 형식과 만들 일을 적어 줘.
3. 위에서부터 따라갈 작업 순서표를 써 줘. 한 줄에는 행동 하나, 그 결과를 넣을 파일과 항목, 다음 작업에서 가져갈 값을 적어 줘. 내 판단이 필요한 지점에는 무엇을 입력할지, AI에게 맡길 지점에는 복사할 프롬프트를 달아 줘.

수량, 필수 조건, 조건부 예외, 선택 과제, 제출 방법을 확인해 빠진 조건을 보충해 줘. 원문에서 확인할 수 있는 절을 연결하고, 정해지지 않은 내용은 미지정으로 표시해 줘. 참여자가 실제로 실행하거나 판정할 칸은 비워 둬.
````

## 입력 템플릿

````text
{미션명_spec.md}를 첨부한다. 제출할 폴더와 파일, 파일별 빈 양식, 선행 결과를 이어받는 작업 순서표를 만들어 줘. 필수와 예시, 선택을 구분하고 표의 열과 순서를 보존해 줘. 한 줄에 행동 하나와 기록할 곳, 다음에 쓸 값을 적어 줘. 수량과 예외를 원문과 대조해 줘.
````

**단계적 추론 유도**

## 환각 검증

**대화 전에 정한 검증 전략**

본 대화 전에 정했다. 답에서 단정한 파일명, 문서 수, 최소 횟수, 필수 여부를 원문 해당 절과 대조한다. 예시를 필수라고 한 경우도 사실 오류로 본다. 새 조건을 알려 준 뒤 다시 원래 조건으로 돌아가는 답은 문맥 끊김으로 기록한다.

정답과 근거를 함께 제시하면 `Pass`다. 모를 때 모른다거나 확인이 필요하다고 밝히고 확인 절차를 제안해도 `Pass`다. 두 기준을 모두 충족하지 못하면 `Fail`이다.
