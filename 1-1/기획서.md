> 버전: 1.1

## 1. 프로젝트 정의

관람한 영화 8편을 다시 보고 싶은 정도에 따라 분류하는 인터랙티브 웹페이지를 만든다. 처음에는 화면을 채우는 **8개의 그래픽 조각(카드 모양)**이 각각 한 편의 영화로 제시된다. 사용자가 카드를 클릭하여 티어를 지정하면 해당 카드에 문자와 도형이 결합된 **그래픽 시그니처**가 생긴다. 여덟 편의 분류가 끝나면 **같은 카드들이 이동하여 S, A, B, C 순서의 티어리스트**를 완성한다.

이 프로젝트의 특징은 완성된 순위표만이 아니라 **8분할 보드 → 티어 지정 → 자동 재배치 → 결과 감상**으로 이어지는 화면 변화에 있다. 디자인 목표를 막연한 ‘세련됨’으로 정의하지 않는다. **손의 입력을 즉시 따라오는 카드, 상태에 따라 형태가 바뀌는 SVG, 화면이 재편되어도 동일한 물체로 인식되는 전환, 작은 반응들이 결합된 일관된 움직임**을 직접 구현하고 검증한다. 기존 웹페이지의 특정 외형이나 효과를 복제하기보다 이러한 작동 원리를 영화 카드에 적용한다.

### 사용자와 목적

- **편집자:** 페이지 제작자 1명. 카드 위치를 바꾸고 각 영화의 티어를 지정한다.
- **검토자:** GitHub 저장소에서 HTML 파일을 내려받아 브라우저로 열고 카드 조작과 결과 화면을 확인한다.
- **최우선 목적:** 영화 카드를 조작하고 화면이 변화하는 경험을 즐기며, 마지막에는 다시 보고 싶은 정도를 명확한 티어리스트로 확인한다.
- **제출:** 두 모델의 HTML 초안과 비교 기록을 이 GitHub 저장소에 포함하고 저장소 링크를 제출한다.

## 3. 티어의 값·정의·상태

티어는 재감상 선호도를 분류한 값이다. 현재는 사용자가 직접 선택하며, 추후에는 수치 상태 `score`를 기준으로 티어 값 `tier`를 결정한다.

| 값 (Value) | 정의 (Definition) | 상태 (State) |
|---|---|---|
| `S` | 매우 높음 | `score ≥ s` |
| `A` | 높음 | `a ≤ score < s` |
| `B` | 보통 | `b ≤ score < a` |
| `C` | 낮음 | `score < b` |
| `null` | 미지정 | `score = null` |

정의는 재감상 선호도의 수준이며, 상태 열은 추후 수치화할 때 적용할 점수 구간이다. 점수가 높을수록 다시 보고 싶은 정도가 크다고 본다. `b`, `a`, `s`는 각각 `B`, `A`, `S`가 되는 최소 점수이며, `b < a < s` 순서로 정한다. 예를 들어 점수가 `a` 이상이고 `s` 미만이면 `A`다. 점수 범위, 산정 방식, 각 티어의 기준 점수는 추후 확정한다.

- **초기 상태:** 8편 모두 `tier = null`이며, 티어 문자와 시그니처를 표시하지 않는다.
- **미지정 처리:** `null`은 아직 판단하지 않았다는 뜻이다. 수치화 이후에도 `score = null`을 먼저 구분하고, 점수가 있을 때만 구간을 판정한다. 미지정을 `0`이나 `C`로 변환하지 않는다.

## 4. 화면 구성

### 4.1 시작: 8분할 보드

- 데스크톱 기준으로 4열 × 2행의 조밀한 보드를 기본안으로 삼는다. 여덟 개의 카드가 하나의 시각적 화면을 구성하도록 바깥 여백과 카드 사이 간격을 일관되게 설계한다.
- 각 카드에는 영화별 그래픽과 제목을 표시한다. 제목은 항상 읽을 수 있어야 한다. 카드를 클릭하면 감독, 개봉 연도, 티어 선택 버튼이 담긴 정보창이 펼쳐진다.
- 초기에는 **S/A/B/C의 티어 사인, 티어별 행, 확정된 순위**가 없다.
- 보드의 배치 순서와 티어는 별개의 정보다. 사용자가 카드를 교환해도 티어는 바뀌지 않는다.
- 화면 상단이나 보드 가장자리에는 간결한 제목, 지정 개수(예: `3 / 8`), 사용법, 초기화 및 결과 관련 조작을 둔다. 보드보다 UI 장식이 앞서지 않도록 한다.

### 4.2 편집: 영화 카드 조작

- **클릭:** 카드의 정보 및 티어 선택 인터페이스를 연다. S/A/B/C 중 하나를 선택하면 해당 카드에 티어 시그니처가 생성된다.
- **드래그:** 카드 한 장을 다른 카드 위로 끌어 놓으면 두 카드의 **보드 위치를 교환**한다. 드래그는 티어를 변경하지 않는다.
- **피드백:** 포인터가 가까워지면 카드의 층위와 내부 선형 그래픽이 약하게 반응한다. 집어 든 카드는 커서의 움직임을 직접 따라오며, 그림자와 기울기로 들어 올린 상태를 드러낸다. 다른 카드 위에 올리면 교환 대상이 명확히 표시되고, 놓는 순간 두 카드가 자신의 새 위치로 정착한다. 반응은 제목을 가리거나 화면 전체를 흔들어서는 안 된다.
- **우발적 클릭 방지:** 드래그로 판정된 제스처에서는 클릭으로 티어 선택창이 열리지 않는다.
- **개별 해제:** 지정된 카드의 티어를 다시 미지정으로 바꿀 수 있다.
- **정보 확장:** 호버 또는 클릭 시 감독, 연도, 영화 제목을 볼 수 있다. 터치 화면에서는 호버에만 의존하지 않는다.

### 4.3 완료: 자동 티어리스트

- **8편 모두 티어를 지정한 순간** 자동으로 전환을 시작한다. 별도의 정렬 버튼은 필요하지 않다.
- 기존 그래픽 카드가 사라져 새 카드로 대체되는 것이 아니라, **같은 카드가 자신의 위치에서 이동**하는 것처럼 보인다.
- 최종 화면에는 전형적인 티어리스트 구조의 **S, A, B, C 네 행**이 모두 표시된다. 비어 있는 티어 행도 남겨 둔다.
- 티어는 S → A → B → C의 내림차순으로 정렬한다. **동일한 티어 안에서는 완료 직전의 보드 순서를 유지**한다. 한 티어 내부에 근거 없는 추가 순위를 만들지 않는다.
- 최종 결과에서도 각 영화의 그래픽, 제목, 티어 시그니처가 식별 가능해야 한다.
- **보드로 돌아가기**를 제공한다. 기존 티어와 배치를 유지한 채 편집 상태로 돌아가서 카드 위치 또는 티어를 수정할 수 있다. 8편이 다시 모두 지정되면 재정렬한다.

### 4.4 결과 다시 보기

- 8편의 티어 지정이 끝나면 **다시 보기(Replay)**로 **시작 보드 → 시그니처 등장 → S/A/B/C 정렬** 과정을 재생할 수 있다.
- 현재 완료된 티어와 보드 순서를 기준으로 재생한다. 실제 드래그와 클릭의 이력을 기록할 필요는 없다.
- **건너뛰기**를 누르거나 재생이 끝나면 최종 티어리스트를 표시한다.
- 재생 중에는 편집 조작을 잠시 멈추고, 결과 화면에서 **보드로 돌아가기**를 선택하면 편집을 이어갈 수 있다.

## 5. 영화별 카드 디자인

### 공통 규칙

1. 영화마다 특징적인 색, 공간, 사물을 골라 카드 그래픽으로 표현한다. 포스터, 스틸, 공식 로고는 사용하지 않는다.
2. 각 카드가 구별되도록 구도와 핵심 모티프를 달리한다. 단, 타이포그래피, 선 굵기 체계, 여백 비율, 재질의 입자감과 레이어 처리 방식은 통일한다.
3. 영화별 그래픽은 `inline SVG`와 CSS만으로 구현한다. 별도의 이미지 파일, 폰트 파일, 네트워크 호출은 요구하지 않는다.
4. 영화 제목은 항상 이미지 위에서 읽히도록 충분한 대비와 공간을 확보한다. 감독과 연도는 정보가 확대된 상태에서도 정확히 읽혀야 한다.
5. 모든 카드가 공유하는 **격자, 선 굵기, 표면 질감, 코너 처리, 정보의 위계, 동작의 시간 규칙**을 먼저 정한다. 서로 다른 영화 그래픽에도 같은 입력은 같은 종류의 반응을 유발해야 한다.

### 영화별 시각화 출발점

아래 표는 영화별 그래픽과 움직임의 초안이다. 영화의 특징을 참고하되, 카드에 맞는 구도로 새롭게 구성한다. 마우스를 올린 카드나 키보드 포커스를 받은 카드만 반응하도록 한다. 마우스와 포커스가 모두 벗어나면 기본 모습으로 돌아간다. 움직임의 크기와 밝기 변화는 카드마다 비슷한 수준으로 맞춘다.

| 영화 | 시각 모티프 초안 | 입력에 반응하는 그래픽 실험 |
|---|---|---|
| 겨울왕국 | 결정의 방사형 대칭, 겹친 투명한 다각형, 차가운 청색의 여백 | 포인터 방향에 따라 결정의 두 투명 레이어가 미세하게 어긋나 깊이가 생긴다. |
| 헤어질 결심 | 산과 바다를 가르는 경계선, 겹쳐진 사선, 안개처럼 분리되는 색면 | 사선과 수평 경계가 다른 속도로 움직이며 두 공간의 분리를 드러낸다. |
| 반지의 제왕 3부작 | 삼중 원호와 먼 산맥, 원형 궤적, 낮은 명도의 금빛 포인트 | 세 개의 원호가 순차적으로 정렬되고 중앙의 원형 흔적이 드러난다. |
| 에브리씽 에브리웨어 올 앳 원스 | 중첩된 원, 복수의 좌표축과 분기, 서로 다른 색면의 충돌 | 동심원 레이어가 서로 다른 방향으로 짧게 이동해 분기를 만든다. |
| 미스 리틀 선샤인 | 노란 원판, 수평 이동선, 작은 사각형들의 리듬과 넓은 햇빛의 면 | 노란 원판과 이동선이 다른 속도로 반응하며 수평 이동감을 만든다. |
| 내일을 향해 쏴라 | 사막의 수평선, 나란히 진행하다 어긋나는 두 궤적, 따뜻한 황토색 | 평행한 두 궤적이 가까워졌다가 조금 멀어지는 짧은 변형을 보인다. |
| 허공에의 질주 | 끊겼다가 이어지는 평행선, 이동의 흔적, 비어 있는 중심과 깊은 색면 | 분리된 선분이 일시적으로 이어졌다가 원래의 간격으로 복귀한다. |
| 위대한 레보스키 | 어긋난 동심원, 길게 뻗은 레인, 반복 무늬의 불규칙한 격자 | 동심원의 중심이 미세하게 이동하며 반복 무늬와 시차를 만든다. |

### 티어 시그니처

- S/A/B/C **문자와 도형을 결합한 표식**을 사용한다. 예를 들어 카드 가장자리의 선형 패턴, 작은 코너 엠블럼, 문자와 결합된 고유 프레임을 사용한다.
- 티어마다 색이 달라도 좋지만, **색만으로 구별하지 않는다.** 반드시 문자와 형태의 차이를 유지한다.
- 사인이 생성될 때 그래픽 전체를 가리지 않고 원래 카드에 **추가로 각인된 레이어**처럼 보여야 한다.
- 아직 정하지 않은 카드에는 해당 사인을 표시하지 않는다.
- 시그니처가 최종 티어리스트에서도 같은 의미로 읽히도록 한다.
- **디자인 실험:** 티어마다 문자 외에 다른 선의 배열을 부여한다. 예를 들어 S는 닫히는 원호, A는 열린 코너, B는 평행 이중선, C는 분리된 직선 구조를 사용한다. 이는 시안이며 실제 그래픽의 의미와 가독성을 보고 조정한다. 단순한 색상 등급표로 끝내지 않는다.
- 시그니처가 생성될 때는 `stroke-dashoffset`, `clip-path`, `opacity` 등으로 **선이 그려지고 형태가 드러나는 짧은 과정**을 만든다.

## 6. 인터랙션 및 상태 규칙

### 상태

1. `unassigned-board`: 8장 모두 티어 없음.
2. `editing-board`: 1~7장 분류 완료. 드래그, 정보 확인, 티어 변경 및 해제 가능.
3. `sorting`: 8장의 티어가 채워져 자동 전환 중. 중복 입력으로 상태가 깨지지 않아야 함.
4. `completed-list`: S/A/B/C 결과 표시. 보드 복귀, 전체 초기화, 다시 보기 가능.
5. `replaying`: 완료된 티어와 순서로 결과를 재생하는 상태. 건너뛰기 또는 재생 종료 시 결과 화면으로 복귀.

편집 중이라도 이미 8편이 지정된 상태에서 **보드로 돌아온 경우**는 유효한 편집 상태다. 단순히 `8/8`이라는 이유로 매번 즉시 정렬하지 않고, **마지막 미지정 카드가 지정되어 7/8 → 8/8이 되는 사건** 또는 편집 완료를 다시 확정하는 조작을 구별한다. 보드로 돌아온 뒤 티어를 바꾼 경우에는 명시적으로 **결과 보기**를 눌러 정렬을 다시 실행할 수 있다.

### 필수 조작

| 조작 | 예상 결과 |
|---|---|
| 카드 클릭 | 정보 및 티어 선택 인터페이스 열림 |
| 티어 선택 | 해당 카드의 사인 생성 또는 변경 |
| 다른 카드 위로 드래그 | 두 카드의 보드 위치 교환 |
| 티어 해제 | 해당 카드의 사인 제거, 미지정 상태 복귀 |
| 7/8 → 8/8 | 자동 정렬 애니메이션 시작 |
| 보드로 돌아가기 | 카드 및 티어 유지, 재편집 가능 |
| 전체 초기화 | 모든 티어를 해제하고 처음의 8분할 보드로 복귀 |
| 다시 보기 | 현재 완료된 결과의 애니메이션 재실행 |
| 건너뛰기 | 재생을 마치고 최종 티어리스트 표시 |

- **Undo 기능은 구현 대상에서 제외**한다. 개별 티어 해제 및 전체 초기화로 수정한다.
- 전체 초기화는 실수로 누르지 않도록 한 번 확인한 뒤 수행한다.
- 카드 위치 교환과 티어 지정이 서로 영향을 주지 않아야 한다.
- 키보드 사용자에게 티어 선택이 가능해야 하며, 드래그를 사용하기 어려운 경우 위치 이동을 위한 대체 조작을 제공하는 편을 권장한다.

## 7. 구현과 실행

### 필수 기술 제약

- 각 모델은 **CSS와 JavaScript를 직접 포함한 HTML 파일 하나**를 만든다. GPT의 결과는 `영화_A_초안.html`, Gemini의 결과는 `영화_B_초안.html`로 저장한다.
- 프레임워크, 빌드 도구, 서버 실행, CDN, 외부 JS, 외부 폰트, 외부 이미지에 의존하지 않는다.
- 파일을 로컬에서 더블클릭하여 열어도 **8분할 보드, 티어 지정, 교환, 자동 정렬, 초기화, 재생** 기능이 동작해야 한다.
- 그래픽은 `inline SVG`와 CSS로 그린다. 필요한 데이터는 HTML 내 JavaScript에 정의한다.
- 애니메이션은 CSS transition, CSS transform 및 표준 Web API로 구현한다. 위치를 바꾸는 전환의 1차 구현 후보는 FLIP(First, Last, Invert, Play) 방식이며, `Element.animate()`를 사용해 실행과 완료 시점을 제어한다. 특정 라이브러리는 요구하지 않는다.
- 접근성: 명시적인 버튼 레이블, 키보드 포커스, 텍스트 대비를 포함한다.

### 실행 중 상태

- 영화별 티어와 카드 순서는 페이지를 열어 둔 동안만 유지한다. 새로고침하거나 파일을 다시 열면 처음의 카드 순서와 8편 모두 미지정인 상태로 돌아간다.
- 편집 결과와 조작 이력을 파일이나 브라우저 저장소에 저장하지 않는다. 다시 보기는 현재 화면에서 완료한 결과를 이용한다.

## 8. 반응형과 모션 설계

### 8.1 주요 동작과 확인 기준

카드 내부 그래픽의 반응, 드래그, 정보창 열기, 티어 시그니처 표시, 정렬, 결과 다시 보기의 여섯 동작을 구현한다. 각 동작은 사용자의 조작에 맞춰 시작하고, 완료 후에는 카드의 위치와 표시가 안정되도록 한다. 아래 표에 화면에서 확인할 동작과 구현 방법을 정리한다.

| 실험 | 화면에서 관찰할 동작 | 구현 접근 및 검수 기준 |
|---|---|---|
| 1. 포인터에 반응하는 그래픽 | 카드 내부의 선과 색면이 포인터 방향에 따라 서로 다른 거리로 움직인다. 카드 외곽은 단정하게 유지한다. | `Pointer Events`, CSS custom properties, 개별 SVG 그룹의 `transform`. 레이어 이동은 대략 2~6px 범위에서 시작해 조정한다. 포인터가 떠나면 원위치로 돌아온다. |
| 2. 카드 드래그 | 드래그 중 카드가 실제 포인터를 따라다니고 그림자, 미세한 확대, 기울기로 높이가 달라진다. 교환 대상은 다른 표현으로 표시된다. | `setPointerCapture()`와 `requestAnimationFrame`을 활용한다. 카드를 누른 뒤 포인터가 정해 둔 거리 이상 움직이면 드래그로 판정하고, 그 전에 손을 떼면 클릭으로 처리한다. 이 기준 거리는 실제 조작을 보며 조정한다. 카드는 포인터를 바로 따라가며, 놓거나 취소하면 이동을 마친다. |
| 3. 정보창 열기 | 카드를 클릭하면 해당 카드의 위치에서 정보창이 펼쳐진다. 닫으면 원래 카드로 포커스를 돌려준다. | 카드의 원래 위치와 확장된 위치를 연결하는 `transform` 또는 FLIP 전환. 220~350ms를 초기 실험 범위로 삼고 `Escape`, 닫기, 포커스 복원을 제공한다. |
| 4. 티어 시그니처 표시 | 선택한 티어의 글자와 선들이 카드에 차례로 새겨진다. 기존 영화 그래픽 위에서 별도의 정보 레이어를 형성한다. | SVG 선의 경로 표시, 마스크 또는 불투명도 전환. 약 180~320ms의 짧은 연출을 우선 시험한다. 새 티어를 지정하면 기존 시그니처는 겹쳐 남지 않는다. |
| 5. 위치 교환과 정렬 | 두 카드를 교환하면 서로의 이전 위치에서 새 위치로 부드럽게 이동한다. 8편이 확정되면 동일한 카드가 4개의 티어 행으로 흩어져 들어간다. | 영화 ID가 동일한 DOM 요소의 이전/다음 좌표를 측정하여 FLIP 이동. 정렬에는 약 650~1000ms의 전체 구간을 처음 실험하고, 그룹별 미세한 시차를 줄 수 있다. |
| 6. 결과 다시 보기 | 8개의 카드가 등장하고 현재 지정한 티어 사인이 차례로 생긴 뒤 같은 카드들이 S/A/B/C 행으로 정렬된다. | CSS와 Web Animations API의 완료 이벤트로 구간 연결. 약 2~4초의 전체 시퀀스를 초기안으로 삼되, **건너뛰기**와 **다시 보기**를 제공한다. |

위 수치는 제작 시 테스트할 **출발값**이며 특정 브랜드의 고유 수치가 아니다. 사용자 입력을 막거나 성능을 떨어뜨린다면 조정한다. ‘스프링 같은 감각’은 필요하지만 반드시 물리 엔진을 사용할 필요는 없다. easing 곡선과 감쇠가 있는 짧은 되돌아옴만으로 충분한지 먼저 검증한다. 불필요한 튕김, 지속적인 흔들림, 전체 화면의 과장된 3D 회전은 사용하지 않는다.

### 8.2 장면 전환의 연출 원칙

- 8분할 보드와 최종 티어리스트는 별도의 그래픽 모음이 아니라 **같은 여덟 객체의 두 배치 상태**다. 카드별 고정 ID, 벡터 아트, 티어 상태를 계속 유지한다.
- 정렬 시 기존 카드를 제거하고 결과 카드가 새로 나타나는 페이드 전환은 피한다. 시작 좌표와 도착 좌표를 잇는 이동을 우선하며, 카드 크기 변화는 내부 텍스트의 안정성과 함께 처리한다.
- 애니메이션 도중 너비가 바뀌거나 화면 방향이 달라지더라도 카드가 화면 밖에 고립되거나 겹쳐 고정되지 않게 한다. 리사이즈 직후에는 좌표를 재계산하고 필요한 경우 안전하게 마지막 상태로 전환한다.
- 시각효과의 층위를 구별한다. **기본 상태**에는 영화 그래픽과 제목, **hover/focus 상태**에는 요소별 움직임의 차이, **drag 상태**에는 카드의 높이와 위치를 바꿀 카드의 강조 표시, **selected 상태**에는 정보 확장, **tiered 상태**에는 지속적으로 남는 사인이 있다.
- 영화 그래픽은 충분히 풍부해야 하지만, 자유로운 움직임이 실제 정보 변경으로 오해되지 않도록 **화면의 움직임과 사용자가 지정한 티어를 구분**한다.
- 단일 화면이 중심이므로 제품 소개 사이트처럼 긴 스크롤을 따라 장면이 바뀌는 효과는 핵심 요구에서 제외한다. 이 프로젝트의 주요 입력은 **클릭, 드래그, 포인터 이동, 상태 전환**이다.

### 8.3 반응형, 접근성, 성능

- **필수 지원:** 데스크톱 최신 브라우저, 특히 약 1280~1440px 폭에서 4×2 구성이 자연스럽게 작동해야 한다.
- **추가 지원 목표:** 태블릿 및 모바일에서는 반응형 웹 디자인(responsive web design)을 적용한다. 넓은 화면의 4열×2행 배치를 좁은 화면에서는 2열로 바꿔 제목과 카드를 읽기 쉽게 유지하고, 필요한 경우 세로 스크롤을 허용한다.
- 마우스 호버 효과는 터치 사용자에게 필수 기능이 되어서는 안 된다. 터치에서도 카드 선택 및 티어 변경이 가능해야 한다.
- 잦은 포인터 반응과 카드 이동에는 우선 `transform`과 `opacity`를 사용한다. 매 프레임 DOM 전체를 다시 구성하거나 레이아웃 계산과 스타일 쓰기를 교차 반복하지 않는다. 화면 전환 전에 위치를 읽고 그다음 애니메이션을 적용한다.
- 포인터 입력에 대한 카드 반응은 가능하면 다음 렌더링 프레임부터 나타나도록 구현하고, 일반적인 60Hz 환경에서 끊김 없이 보이는 것을 검수 목표로 삼는다. 실제 프레임 속도를 측정하지 않았다면 성능을 충족했다고 단정하지 않는다.
- 동작은 빠른 반응, 가벼운 기울기, 섬세한 그림자, 일관된 easing, 충분한 정착 시간을 중심으로 설계한다. 과도한 탄성, 불필요한 3D 회전, 긴 로딩 연출은 피한다.
- 정렬 도중 크기가 바뀌거나 위치가 이동해도 제목이 흐려지거나 화면 밖으로 사라지지 않게 한다.

## 9. 우선순위

사용자가 지정한 우선순위를 그대로 적용하며, 하위 우선순위의 시각효과 때문에 상위 우선순위의 동작 안정성을 희생하지 않는다.

1. **단일 HTML 구현 안정성**: 로컬 실행, 실행 중 상태 유지, 결과 다시 보기, 핵심 동작 오류 방지.
2. **시각적 완성도**: 8분할 보드와 최종 티어리스트의 구도, 타이포그래피, 색과 여백.
3. **영화별 그래픽의 해석력**: 8편의 시각 모티프가 서로 다르면서 한 시리즈로 보이는지.
4. **인터랙션의 세련됨**: 미세한 물리감, 정렬 및 시그니처 애니메이션의 디테일.

## 10. 완성 기준 체크리스트

### 기능 및 데이터: 필수

- [ ] 각 HTML 초안을 로컬에서 열면 외부 리소스 요청이나 설치 없이 핵심 기능이 실행된다.
- [ ] 처음 접속한 깨끗한 상태에는 정확히 8장의 카드가 있고 모든 티어가 미지정이다.
- [ ] 영화 제목, 감독, 연도 정보가 8편 모두 정확하며 〈반지의 제왕〉은 3부작 전체를 한 카드로 취급한다.
- [ ] 각 카드에 영화별 오리지널 SVG 그래픽이 나타난다.
- [ ] 클릭으로 S/A/B/C를 선택, 변경, 해제할 수 있다.
- [ ] 드래그로 두 카드의 위치를 교환하며 티어에는 영향을 주지 않는다.
- [ ] 카드를 드래그한 직후 의도치 않게 클릭 메뉴가 열리지 않는다.
- [ ] 8번째 티어 지정 시 자동으로 최종 정렬된다.
- [ ] 최종 결과는 S, A, B, C 네 행으로 구성되며 빈 행도 표시된다.
- [ ] 같은 티어의 카드들은 마지막 보드 순서를 유지한다.
- [ ] 보드로 돌아가 기존 정보 수정 후 결과를 다시 볼 수 있다.
- [ ] 개별 해제와 전체 초기화가 정상 동작하며 Undo 없이 수정할 수 있다.
- [ ] 편집 결과와 조작 이력을 별도로 저장하지 않으며, 새로고침하거나 파일을 다시 열면 초기 카드 순서와 모든 티어가 미지정인 상태로 시작한다.
- [ ] 리모트 저장소와 연결된 로컬 폴더의 `영화_A_초안.html`과 `영화_B_초안.html`을 각각 브라우저로 열어 같은 기준으로 확인한다.
- [ ] 완료된 결과를 시작 보드 → 시그니처 → 정렬 순서로 다시 볼 수 있다.

### 시각 및 접근성: 필수

- [ ] 데스크톱의 첫 화면은 8개의 카드로 구성된 일관된 보드처럼 보인다.
- [ ] 여덟 그래픽은 구별되면서 같은 디자인 시리즈로 읽힌다.
- [ ] 티어 사인은 문자와 도형을 결합하며 미지정 카드에는 나타나지 않는다.
- [ ] 제목은 항상 읽을 수 있고 감독과 제작연도에 접근할 수 있다.
- [ ] 시그니처 생성과 카드 정렬에서 영화 카드의 동일성이 유지된다.
- [ ] 카드 내부 SVG가 입력에 반응하지만 영화 제목과 다른 카드의 식별성을 해치지 않는다.
- [ ] 드래그하는 카드는 포인터의 움직임을 그대로 따라가며, 어느 카드와 위치가 바뀔지 명확하게 표시된다. 드래그를 취소하면 카드는 원래 위치로 돌아가며, 화면에 떠 있거나 이후 조작이 멈추는 오류가 발생하지 않는다.
- [ ] 클릭한 카드에서 정보 패널로 이어지는 전환이 있고, `Escape`로 닫으면 포커스가 원래 카드로 복귀한다.
- [ ] 티어 시그니처가 SVG와 텍스트로 결합되어 생성되며 해제 또는 변경 시 시각적 잔상이 남지 않는다.
- [ ] 여덟 카드가 보드에서 네 행으로 이동하는 전환에서 ID, 작품별 그래픽, 티어 상태가 유지된다.
- [ ] 결과 재생 중 건너뛰기와 다시 보기가 가능하며, 재생을 반복해도 정렬 결과가 바뀌지 않는다.
- [ ] 키보드로 티어를 선택할 수 있고 포커스가 식별된다.

### 추가 달성 목표

- [ ] 태블릿과 모바일에서 터치 조작 및 적절한 반응형 배치를 제공한다.
- [ ] 좁은 화면에서도 카드의 그래픽과 제목을 알아볼 수 있다.
- [ ] 카드 위치 이동을 위한 키보드 대체 조작을 제공한다.
- [ ] 물리적인 반응과 전환 애니메이션이 정교하되 방해되지 않는다.
- [ ] 포인터 이동 중 시각 반응이 매끄럽고 프레임 단위의 불필요한 재배치가 발생하지 않는다. 실제 브라우저에서 반복 조작해 확인한다.

## 11. 산출물과 제작 범위

이 `기획서.md`를 두 모델의 공통 제작 기준으로 사용한다. 두 모델에 같은 기능과 화면을 요청하고, 결과 파일명만 다음과 같이 구분한다.

| 구분 | 모델 | 초안 파일명 |
|---|---|---|
| A | GPT | `영화_A_초안.html` |
| B | Gemini | `영화_B_초안.html` |

각 HTML 파일에는 영화별 그래픽, CSS, JavaScript, 데이터를 모두 포함한다.
외부 파일이나 서버 없이 브라우저에서 바로 열려야 한다.
저장한 두 HTML 파일을 각각 열어 같은 동작으로 완성 기준을 확인한다.
두 초안의 비교 결과와 수정 내용은 `미션1_기록.md`에 작성할 예정이다.

### 고려했으나 제외한 요소

| 요소 | 사용하지 않는 이유 | 적용 방식 |
|---|---|---|
| 외부 영화 포스터 | 파일 용량이 커지는 것을 피하고, 작품마다 다른 이미지 해상도를 맞추는 작업을 줄이기 위해서다. | 영화별 그래픽을 inline SVG와 CSS로 그린다. |
| 실행 취소 (`Undo`) | 개별 카드의 티어를 해제해 다시 지정할 수 있으면 충분하다고 판단했다. | 개별 티어 변경·해제와 전체 초기화를 제공한다. |
