먼저 앞 답변에서 두 곳을 바로잡겠습니다.
1. README 양식을 문서마다 한 줄씩 소개하는 형태로 만들었습니다. 하지만 원문은 소개를 문서마다 한 줄씩 쓰는지, 전체를 한 줄로 쓰는지 정하지 않았습니다. 이 부분은 [해석]으로 표시했어야 했습니다.
2. ".md 대신 .pdf를 써도 된다"는 말은 네 문서에만 해당합니다. README 줄에는 "또는 PDF" 표기가 없습니다.

행 번호는 첨부 파일 기준이고, 원문을 검색해 위치를 다시 확인했습니다.

## 1. 제출할 문서의 종류

답: 필수 문서는 네 종류입니다.
1. LLM 모델 비교와 선정 보고서(41행): 같은 과업 프롬프트를 세 종 이상의 모델에 넣고, 결과를 같은 기준으로 비교해 정리한 보고서입니다. 비교표와 선정 결론으로 구성합니다(43~44행).
2. 시스템 설계 문서(52행): 페르소나, 시스템 프롬프트, 예시, 검증 전략, 개선 이력을 한곳에 모은 설계 기록입니다(54행).
3. 실행 로그(67행): 설계한 프롬프트로 실제 대화를 한 기록입니다. 미션을 하는 동안 진행한 작업도 함께 남깁니다(69행).
4. 미해결 기록(78행): 프롬프트로 원하는 결과를 얻지 못한 과업을 남긴 기록입니다(80행).

해당 절: §2 머리말(39행), §2-1부터 §2-4까지(41, 52, 67, 78행), §2 끝 문단(87행)과 그 아래 트리(92~95행)입니다.

판단 근거:
- 39행에서 "4가지 산출물"이라고 개수를 밝힙니다.
- 87행은 같은 문서들을 줄인 이름으로 다시 나열하고 "네 문서"라고 부릅니다.
- 92~95행의 트리는 파일마다 "산출물 1"부터 "산출물 4"까지 번호를 붙였습니다.
- 세 곳의 개수와 순서가 서로 맞습니다.
- 87행의 "비교 보고서"와 "설계 문서"는 §2-1과 §2-2 제목을 줄인 이름으로 보았습니다. 순서와 트리 번호가 같다는 점을 근거로 한 추론입니다.

함께 확인한 조건:
- 실제로 제출하는 것은 문서 자체가 아니라 저장소 URL입니다. 문서는 그 저장소에 올립니다(87행).
- 문서 형식은 Markdown 또는 PDF입니다(87행).
- README.md는 선택 사항이라 네 종류에 들어가지 않습니다(96행).
- 원문은 보너스 결과물을 별도 문서로 정하지 않았고, 어디에 둘지도 정하지 않았습니다(§5).

## 2. 영문 파일명과 README의 사용 조건

답(문서 파일명): 원문 트리에 예시로 나온 이름은 다음과 같습니다. 네 파일은 모두 docs/ 폴더 안에 있습니다(91행).
- 산출물 1: model-comparison.md(92행)
- 산출물 2: system-design.md(93행)
- 산출물 3: run-log.md(94행)
- 산출물 4: unresolved.md(95행)
- 네 줄 모두 "또는 PDF"가 붙어 있으므로 PDF로 내도 됩니다.

답(README 사용 조건):
- 파일명은 README.md입니다. 트리에서는 docs/ 밖, 저장소 루트에 있습니다(96행).
- 쓸지 말지는 선택입니다(96행 "선택").
- 쓴다면 네 문서의 순서와 한 줄 소개를 담습니다(96행).
- 원문에서 README를 언급한 곳은 96행 한 곳뿐입니다.

원문이 정하지 않은 것:
- 한 줄 소개를 문서마다 쓸지, 전체에 한 줄만 쓸지
- README를 PDF로 내도 되는지

해당 절: §2 끝 문단(87행)과 그 아래 트리(89~97행)입니다.

판단 근거:
- 파일명과 산출물 번호의 대응은 트리 각 줄의 괄호 주석에서 확인했습니다(92~95행).
- 87행은 "폴더 구조는 아래를 참고할 수 있다"고 합니다. 그러므로 트리에 나온 파일명, docs/ 폴더명, README 위치는 모두 참고용 예시입니다. 반드시 그 이름을 써야 하는 것은 아닙니다.
- 원문이 정한 것은 이름이 아니라 조건입니다. 네 문서를 한 폴더에 모으고, Markdown 또는 PDF로 쓰는 것입니다(87행).
