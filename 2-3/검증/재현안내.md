# 미션7 수정 전후 실행 증거

2026년 11월 13일 macOS의 Chrome 157.0.8103.51에서 저장된 HTML 네 판본을 실행했다. 화면 크기는 1000×760이며, HTML을 `file://`로 직접 열었다. 조작과 측정은 Codex가 수행했다. JSON과 로그의 시각은 UTC이며 한국 시각은 여기에 9시간을 더한다.

## 브라우저 로그와 측정값

- [브라우저콘솔.log](브라우저콘솔.log): 각 상황의 시작 시각, 조작 순서, 실제 console 이벤트, `pageerror`, `requestfailed` 수를 기록했다. `[ACTION]`은 검사 도구가 기록한 조작이며, `[BROWSER CONSOLE]`은 페이지에서 나온 메시지다. 이번 9개 상황의 세 이벤트 수는 모두 0이다.
- [실행결과.json](실행결과.json): 브라우저 버전, 화면 크기, 각 HTML의 Git 위치와 SHA-256, 전환 중 스크롤 위치, 실제 복사 문자열의 길이와 원문 일치 여부, 읽기 전환 전후 위치와 프레임, 인쇄 구성 수, 결과 파일의 SHA-256을 담았다.
- [인쇄 전 전체 페이지](수정3_인쇄_전_전체페이지.png), [인쇄 후 전체 페이지](수정3_인쇄_후_전체페이지.png): 두 PDF를 페이지별로 렌더해 순서대로 배치했다. 각 칸의 번호는 PDF 쪽수다.

## 다시 실행하는 방법

필요한 도구는 Node.js, Playwright와 녹화용 FFmpeg, 설치된 Chrome, `ffmpeg`와 `ffprobe`, ImageMagick의 `magick`, Poppler의 `pdftoppm`이다. Python 변환 스크립트는 표준 라이브러리를 사용한다. 이번 실행의 Playwright 버전은 `1.66.0-alpha-1794252756000`이다.

저장소의 Git 이력을 받은 뒤 저장소 최상위 폴더에서 실행한다. `PLAYWRIGHT_MODULE`에는 환경에 설치된 Playwright 모듈 폴더의 절대 경로를 넣는다. 일반적인 Node 모듈 검색으로 Playwright를 찾을 수 있는 환경에서는 이 변수 설정을 생략할 수 있다.

```sh
PLAYWRIGHT_MODULE='/설치된/node_modules/playwright' \
  node 2-3/검증/재현검사.mjs /tmp/codyssey-2-3-evidence
python3 2-3/검증/증거변환.py /tmp/codyssey-2-3-evidence
```

GIF 캡션과 PDF 쪽수 표시는 macOS의 Apple SD Gothic Neo를 사용한다. 다른 환경에서는 `EVIDENCE_FONT`에 사용할 한국어 글꼴 파일 경로를 지정한다.

첫 명령은 Git에서 각 판본을 읽어 임시 폴더의 `raw/`에 저장하고, Chrome에서 전후 작업을 실행한다. 이어 화면 PNG, 원본 WebM, 실제 실행 로그와 두 PDF를 만든다. 두 번째 명령은 WebM을 비교 GIF로 변환하고 PDF의 모든 쪽을 PNG로 렌더한다. 결과는 지정한 임시 폴더에서 확인한다.

손으로 확인할 때도 같은 Git 위치의 HTML을 열어 첫 표의 작업을 순서대로 수행한다. 세부 재현 조건과 측정값은 실행결과 JSON, 실행 순서는 브라우저 콘솔 로그에서 대조한다.
