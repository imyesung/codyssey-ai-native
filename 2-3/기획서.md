# Codyssey Mission AI 활용법: 최종 기획서

## 대상 사용자

코디세이 입학연수 동료와 미션톤 발표자다.

## 사용 목적

실제 과제에서 쓴 AI 요청과 결과를 공유한다. 발표자는 키보드로 장면을 넘기고, 동료는 발표 뒤 같은 파일을 읽으며 요청문을 가져간다. 수정 전후 녹화, 피드백 도식, 레이아웃 사례를 먼저 보고 그 결과를 받은 요청을 읽는다.

기준은 11월 10일 발표에 사용한 GPT 계열 HTML이다. 지인에게 두 파일을 열어 비교하도록 했더니 GPT 버전의 전반적인 만듦새가 좋고, 전환 인터랙션은 Claude 버전이 좋다는 의견을 받았다. 발표본의 내용과 개인 수정은 유지하고, 페이지 이동을 보완했다.

## 최종 파일

`미션AI활용법_최종.html` 하나를 브라우저에서 연다. 내부 버전은 `v4`다. CSS, JavaScript, 녹화, 캡처, 인쇄용 정지 화면을 포함해 별도 설치나 서버가 필요 없다. 이 기획서와 제작검증기록을 함께 평가 자료로 둔다.

## 화면 구성과 동작

| 화면 | 확인할 내용과 조작 |
| --- | --- |
| 표지와 소개 | 발표 때 쓴 제목, 소개 문장, 작성자와 날짜를 유지했다. 버튼이나 방향키로 시작한다. |
| 네 가지 재현 사례 | 저장 위치, 영화 추가, 초기화, 2배 확대를 차례로 본다. 전후 녹화를 함께 멈추거나 재생하고, 전체 장면과 코드는 따로 연다. |
| 같은 손동작 | Prompt 1의 구절로 영상의 확인 지점을 짚는다. |
| 피드백 도식 | SVG의 네 행과 세 열을 한 화면에 맞춘다. 원문 표는 따로 펼친다. Prompt 2를 읽거나 복사한다. |
| 레이아웃 레퍼런스 | OpenAI, Thariq Shihipar, Simon Willison, Maggie Appleton, Robin Rendle, Frank Chimero, Mike Bostock 순서다. 한 번에 한 이미지와 감상을 읽고 원문을 열 수 있다. |
| 사례 검색과 비교 기준 | Prompt 3~6을 읽는다. 개별 복사와 여섯 요청문 전체 복사를 제공한다. |
| Q&A | 마지막 요청문으로 돌아가거나, 자료를 처음부터 읽거나, 표지로 돌아간다. |

표지와 소개, 본문, Q&A의 순서는 기존 발표와 같다. 저장 위치에서 `→`를 네 번 누르면 영화 추가, 초기화, 2배 확대, 같은 손동작에 도착한다. `←` 네 번은 정확한 역순이다. 긴 글에서는 이전 내용과 겹치게 움직이고, 일곱 레퍼런스는 하나씩 방문한다. 빠르게 여러 번 눌러도 마지막 이동 목표에 도착한다.

위치가 바뀔 때는 380ms 동안 스크롤하고, 같은 자리에서 화면 내용이 바뀔 때는 짧게 나타나게 했다. 시스템의 ‘움직임 줄이기’ 설정에서는 전환 애니메이션을 끄고 녹화도 정지 상태로 시작한다. 이 설정에서도 직접 재생할 수 있다.

## 발표 뒤의 이용

**요청문 복사.** 각 요청 바로 아래에 복사 버튼을 두었다. Prompt 1~6의 원문과 줄바꿈은 발표본 그대로다. 실제 clipboard 쓰기가 성공한 뒤에만 완료를 표시한다. 권한이 없으면 원문을 선택한 창을 열어 `⌘C` 또는 `Ctrl+C`로 복사하게 한다. `Esc`로 닫으면 누르던 버튼으로 돌아온다.

**자료 읽기.** 왼쪽 목차의 ‘자료 읽기’를 누르면 영상을 멈추고 현재 위치에서 스크롤로 읽는다. ‘발표로 돌아가기’로 같은 위치의 방향키 이동을 다시 사용할 수 있다. Q&A에서는 자료를 처음부터 읽을 수 있다.

**인쇄.** 네 사례를 모두 펼치고, 각 전후 녹화의 57번 프레임을 정지 화면으로 보여 준다. 재생 상태와 선택한 탭에 관계없이 같은 여덟 장면을 인쇄한다. 일곱 레퍼런스, 도식과 원문 표, 코드와 여섯 요청문도 함께 인쇄한다.

## 필요한 자료

녹화와 비교 코드는 기존 `1-4`, SVG는 `1-3`에서 가져온 발표 자료다. 여기에 여섯 요청문과 레이아웃 레퍼런스 일곱 건의 캡처, 저자와 발행처의 원문 링크를 사용한다. HTML 안에 녹화, 캡처와 인쇄용 정지 화면을 포함한다.

## 완료 기준

1. 네 사례의 전후 영상, 전체 장면과 코드를 열 수 있다. 저장 위치에서 네 번의 방향키 왕복이 같은 순서를 유지한다.
2. 도식이 좁은 세로 화면과 낮은 가로 화면에서도 고정 목차 아래 가시 영역에 들어온다. 일곱 레퍼런스를 양방향으로 빠짐없이 읽는다.
3. 여섯 요청문을 복사해 원문과 대조하면 본문과 줄바꿈이 같다. 복사를 거부한 조건에서도 선택된 원문을 가져갈 수 있다.
4. 자료 읽기 전환은 보고 있던 위치를 유지한다. 인쇄에서는 네 사례의 전후 정지 화면 여덟 개와 일곱 레퍼런스가 보인다.
5. 네트워크를 끄고 HTML 하나만 열어도 내장 녹화, 캡처, 도식과 요청문을 확인할 수 있다.

## 추가 기능

원격 발표 조작과 청중 응답 수집을 후속 기능 후보로 둔다.

## 한계 및 비목표

1. 제공 범위는 기존 녹화와 코드, 도식, 요청문의 열람과 재사용이다. AI를 실행해 새 분석 결과를 만드는 기능은 후속 개발 항목으로 둔다.
2. 최종본의 기기 검증은 Mac의 Chrome과 다섯 가지 브라우저 화면 크기를 기준으로 했다. 실물 휴대폰, 평가실 기기, Safari와 브라우저 200% 확대는 후속 확인 항목이다.
3. 외부 사이트 화면은 채택한 발표본의 내장 캡처와 원문 링크로 제공한다. 이 방식은 과제의 HTTPS 사진 삽입 조건과 형식 차이가 있다. 외부 캡처의 별도 사용 허락은 기존 출처 기록에서 미확인 상태다.

## 검증 방법

같은 조작을 수정 전후에 반복한다. 발표본의 녹화 자료와 SVG, 요청문을 최종본과 대조하고, 브라우저에서 위치, 크기, 프레임과 실제 clipboard 문자열을 읽는다. 읽기 전환 전후 위치를 비교하고, 인쇄 PDF를 열어 네 사례와 일곱 레퍼런스를 확인한다. 확인한 환경과 수치는 제작검증기록에 적는다.

최초 제작에는 GPT-6 Astra와 Claude Opus 5.5를 사용했다. 이번 수정과 문서 정리, 자동 브라우저 검사는 Codex로 수행했다. 사람이 제공한 피드백과 AI가 수행한 재검증은 제작검증기록에서 나누어 적었다.
